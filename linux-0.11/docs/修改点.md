# Linux 0.11 → RISC-V 移植修改点记录

本文档对照官方 Linux 0.11 源码（git 基线 `c39fe67`，kernel.org
Historic/old-versions），逐条记录移植过程中对原版代码的**修改点**。

分两部分：

- **一、架构级替换/新增**：RISC-V 特有的基础设施，原版 x86 代码没有对应物；
- **二、对原版逻辑的修改**：在沿用原版模块时修正的 bug 或语义差异——
  这部分是调试中最容易踩坑、也最有参考价值的地方。

---

## 一、架构级替换/新增（RISC-V 特有）

| 模块 | 文件 | 说明 |
|---|---|---|
| 引导 | `boot/head.s` | M-mode 入口：清零 BSS、引导栈、PMP 配置、跳 main() |
| 陷阱/上下文 | `kernel/trap.S` | `trap_entry`/`ret_from_trap`/`switch_to`，140B trapframe |
| 异常分发 | `kernel/traps.c` | mcause 分发、系统调用、定时器、页错误 |
| 时钟 | `kernel/sched.c` + CLINT | 用 CLINT_MTIMECMP 产生 100Hz 中断（HZ=100） |
| 控制台 | `kernel/chr_drv/console.c` | 16550 UART（0x10000000）轮询收发 |
| 块设备 | `kernel/blk_drv/ramdisk.c` | rootfs 镜像直接 `.incbin` 进内核，块读写映射到内存 |
| 内存管理 | `mm/memory.c` + Sv32 | 用户任务独立页目录；内核 M-mode 裸访问 + `translate_user()` |
| 系统调用 ABI | `kernel/trap.S`/`traps.c`/`include/unistd.h` | ecall，a7=调用号，a0-a2=参数 |
| 链接 | `kernel.ld` | 布局 .text/.rodata/.data/.rootfs/.bss，`_kernel_end` |
| rootfs 生成 | `tools/mkfs.c` + `rootfs.S` | Minix v1 镜像生成与 `.incbin` 嵌入 |
| 用户程序 | `user/` | ELF32 静态链接、crt0、shell、libc 封装、测试程序 |

## 二、对原版逻辑的修改

### 1. Sv32 PTE 编码（`include/linux/mm.h`、`mm/memory.c`）

- **原版**：x86 页表项格式。
- **问题**：早期移植把物理页地址直接放进 PTE（`phys | flags`），内核自查
  页表自洽，但 CPU 硬件翻译把 PPN 字段（Sv32 占 bits[31:10]）解析成错误
  值 → 首次进入用户态取指即 `exec_page_fault` 死循环。
- **修改**：统一按 Sv32 编码/解码：

```c
/* 编码：pte = (phys >> 12) << 10 | flags */
static inline unsigned long phys_ppn(unsigned long phys)
{
	return (phys >> 12) << PTE_PPN_SHIFT;
}
/* 解码：phys = ((pte >> 10) & PTE_PPN_MASK) << 12 */
static inline unsigned long pte_phys(unsigned long pte)
{
	return ((pte >> PTE_PPN_SHIFT) & PTE_PPN_MASK) << 12;
}
```

### 2. PMP 配置（`boot/head.s`）

- **问题**：QEMU 在未配置 PMP 时，S/U 模式所有访存均失败
  （mret 到用户态第一条指令就 `fault_fetch`）。
- **修改**：启动早期配置 `pmpaddr0 = -1`、`pmpcfg0 = 0x0f`
  （TOR，R|W|X，覆盖全部地址）。

### 3. 用户态 ecall 声明 t0/t1 clobber（`include/unistd.h`、`lib/open.c`、
    `lib/_exit.c`、`user/uprint.c`）

- **原版**：x86 `int 0x80` 只改 eax；内联汇编 clobber 只列返回寄存器。
- **问题**：本移植的 M-mode trap 入口用 t0/t1 做临时寄存器，每次 ecall 后
  用户态 t0/t1 变垃圾值（t1 变成 mepc）。gcc 认为 ecall 只改 a7/a0/a1/a2，
  继续在调用间使用 t0/t1 → 表现是输出每行只打一个字符、逻辑错乱。
- **修改**：`_syscall0/1/2/3` 宏与手工 ecall 的 clobber 列表加 `"t0","t1"`，
  由编译器保存/恢复。

### 4. jiffies 递增（`kernel/traps.c`）

- **原版**：x86 在汇编定时器入口递增 `jiffies`。
- **问题**：移植后定时器走 C 路径，漏了 `jiffies++` → `alarm()`/`times()`
  永远不触发（SIGALRM 测试卡死）。
- **修改**：定时器分支（mcause=0x80000007）里先 `jiffies++` 再重设
  CLINT_MTIMECMP、调 `do_timer()`。

### 5. clear_bit 返回语义（`fs/bitmap.c`）

- **原版**：x86 `btrl + setnb` —— 位**原本已清除**时返回 1。
- **问题**：移植的 C 版返回“原本是否置位”（1=成功清除），与调用方
  判断相反 → 首次正常释放 inode/block 被误判为 double-free，直接
  `Kernel panic: free_block: bit already cleared`。
- **修改**：`return old ? 0 : 1;`。

### 6. mount_root 位图只读统计（`fs/super.c`）

- **原版**：统计空闲 inode/zone 时用 `set_bit` 遍历位图，会把所有空闲位
  标成已用。
- **问题**：首次创建文件即 ENOSPC（inode/zone 位图全 1）。
- **修改**：新增只读 `test_bit`，统计时不改动位图。

### 7. sys_creat 补 O_WRONLY（`fs/open.c`）

- **原版**：`sys_open(pathname, O_CREAT | O_TRUNC, mode)`，缺少
  `O_WRONLY`（x86 原版同样缺，但 open_namei 内部有兜底）。
- **修改**：补全为 `O_CREAT | O_TRUNC | O_WRONLY`，语义完整。

### 8. exec 设置 end_code（`fs/exec.c`）

- **原版**：`do_execve` 只设置 start_code/end_data/brk。
- **问题**：`end_code` 恒为 0 → `sys_brk` 的边界判断失效，
  `brk(0)` 会把堆清到 0（堆分配测试失败）。
- **修改**：加载段时同步维护 `end_code = max(end_code, vaddr+memsz)`。

### 9. fork 不再重复 mepc += 4（`kernel/fork.c`）

- **原版**：`copy_process` 复制 trapframe 后 `tf->mepc += 4`。
- **问题**：本移植的 `trap_handler` 处理 ecall 时已 `mepc += 4`，再
  加一次会让子进程从错误 PC 恢复（跳过 ecall 后续指令，行为随机错乱）。
- **修改**：删掉 `copy_process` 里的 `tf->mepc += 4`。

### 10. 控制台 cli/sti 嵌套安全（`kernel/chr_drv/console.c`、
     `include/asm/system.h`）

- **原版**：`con_write`/`con_poll` 内部 `cli(); ...; sti();`。
- **问题**：`con_poll` 已 `cli()` 时，内部 `copy_to_cooked → con_write`
  的 `sti()` 会提前重开中断 → 定时器与 UART 队列竞态，长时间输出后
  丢字符甚至卡死。
- **修改**：新增 `save_flags()/restore_flags()`，按进入时的中断标志恢复，
  支持嵌套。

### 11. tty_read 轮询等待整行（`kernel/chr_drv/tty_io.c`）

- **原版**：`sleep_if_empty` 只睡眠，由控制台中断唤醒。
- **问题**：移植改为 busy-wait 轮询后，`sleep_if_empty` 只在队列
  **完全为空**时轮询 UART；当“已输入字符但还没凑成整行”（canonical
  等回车）时直接返回，主循环自旋不读 UART → **输入一个字符就卡死**。
- **修改**：tty_read 的等待改成内联轮询循环，`con_poll()` 直到
  队列非空且 canonical 下 data>0（整行完成）才继续。

### 12. 退格支持 BS 与 ECHOE（`kernel/chr_drv/tty_io.c`）

- **原版**：ERASE 只认 DEL(0x7f)，回显 DEL 字符，termios 无 ECHOE。
- **问题**：部分终端退格发 BS(0x08)；且不回显 `\b \b` 导致屏幕上
  字符不擦除，看起来“退格不正常”。
- **修改**：`c == ERASE_CHAR || c == 8` 都按删除处理；控制台 termios
  加 `ECHOE`，删除时回显 `\b \b`（控制字符回显两套）。

### 13. buffer 哈希链 NULL 保护（`fs/buffer.c`）

- **原版**：`remove_from_queues` 直接 `bh->b_next->b_prev = ...`，x86 上
  第 0 页被映射掩盖了 NULL 解引用。
- **问题**：RISC-V 上 NULL 解引用即 fault。
- **修改**：`insert_into_queues`/`remove_from_queues` 对 `b_next`/`b_prev`
  判空。

### 14. do_div 用 rv32 硬件除法（`kernel/vsprintf.c`）

- **原版**：x86 32 位除法内联汇编。
- **修改**：rv32imac 自带 `div`/`rem` 指令，`do_div(n, base)` 直接用
  硬件除法，避免软除法实现。

### 15. stdarg 换 __builtin_va_list（`include/stdarg.h`）

- **原版**：x86 栈传参的 va_list 布局。
- **问题**：rv32 按寄存器传参，x86 布局不可用。
- **修改**：直接使用编译器内置 `__builtin_va_*`。

### 16. unistd.h 声明块按 __LIBRARY__ 隔离（`include/unistd.h`）

- **原版**：用户态函数声明在所有包含者可见。
- **问题**：测试程序 `#define __LIBRARY__` 用 `_syscallN` 宏内联定义
  同名函数时，与 unistd.h 的 extern 声明类型冲突（如 `off_t` vs `int`）。
- **修改**：声明块用 `#ifndef __LIBRARY__` 包裹，`__LIBRARY__` 使用者
  只看到宏与调用号。

### 17. sys_call_table 位置与数量（`kernel/sys.c`、`include/linux/sys.h`）

- **原版**：调用表在 `kernel/system_call.s` 附近。
- **修改**：73 项 `sys_call_table[]` 移到 `kernel/sys.c`，
  `include/linux/sys.h` 只留 extern 声明；`ftime/ptrace/acct` 等
  返回 -ENOSYS 的桩函数补齐。

### 18. init/main.c 启动流程调整

- 去掉 x86 特定初始化（8259A、软驱、键盘、硬盘等）。
- `ROOT_DEV = 0x0101`（ramdisk：主 1 次 1），挂载根文件系统。
- 定时器用 CLINT；`startup_time = 0`（无 RTC）。
- 保留 `kernel_thread(init)` 结构：init 打开 /dev/tty0 → spawn shell。

### 19. shell 内置命令与输入处理（`user/sh.c`，用户态新增）

- 内置 `cd/pwd/echo/ls/exit`；其余按 `/bin/<cmd>` 执行。
- 支持多行粘贴（一次 read 分多条执行）、参数 argv 清零（避免无参命令
  读到栈垃圾）、退格（DEL/BS）。

### 20. 测试程序（`user/t_*.c`，用户态新增）

- `t_up`（printf 回归）、`t_fork`、`t_cow`、`t_fs`、`t_pipe`、
  `t_sig`、`t_sched`、`t_stress`（综合五阶段压力）。
- 详见[测试指南](测试指南.md)。

## 排查速查

| 现象 | 对应修改点 |
|---|---|
| 进用户态第一条指令反复 fault | 1（PTE 编码）、2（PMP） |
| 每行只打一个字符 | 3（ecall t0/t1 clobber） |
| alarm 不触发 / 测试卡死 | 4（jiffies++） |
| FS 首次创建文件 ENOSPC / double-free panic | 5、6（位图语义） |
| brk 堆分配异常 | 8（end_code） |
| fork 后子进程行为错乱 | 9（mepc） |
| 长时间输出丢字/卡死 | 10（cli/sti 嵌套） |
| 输入一个字符卡死 | 11（tty_read 轮询整行） |
| 退格不擦字 / 不生效 | 12（BS + ECHOE） |
| 内核空指针 crash | 13（buffer 链 NULL 保护） |
