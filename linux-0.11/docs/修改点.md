# Linux 0.11 → RISC-V 移植修改点记录

本文档对照官方 Linux 0.11 源码（git 基线 `c39fe67`，kernel.org
Historic/old-versions），逐条记录移植过程中对原版代码的**修改点**。

分两部分：

- **一、架构级替换/新增**：RISC-V 特有的基础设施，原版 x86 代码没有
  对应物。下面按模块逐个展开，面向初学者。
- **二、对原版逻辑的修改**：沿用原版模块时修正的 bug 或语义差异——
  这部分是调试中最容易踩坑、也最有参考价值的地方。

---

## 一、架构级替换/新增（RISC-V 特有）

总览：

| 模块 | 文件 | 一句话说明 |
|---|---|---|
| 引导 | `boot/head.s` | M-mode 入口：清零 BSS、引导栈、PMP、跳 main() |
| 陷阱/上下文 | `kernel/trap.S` | 进 trap 保存现场、返回恢复现场、任务切换 |
| 异常分发 | `kernel/traps.c` | 按 mcause 分发：系统调用/定时器/页错误/死机 |
| 时钟 | `kernel/sched.c` + CLINT | 100Hz 定时中断 |
| 控制台 | `kernel/chr_drv/console.c` | 16550 UART 轮询收发 |
| 块设备 | `kernel/blk_drv/ramdisk.c` | rootfs 当块设备读写 |
| 内存管理 | `mm/memory.c` + Sv32 | 用户任务页表 + 内核查表访问用户内存 |
| 系统调用 ABI | trap.S/traps.c/unistd.h | ecall + a7 调用号 |
| 链接 | `kernel.ld` | 内核镜像布局 |
| rootfs 生成 | `tools/mkfs.c` + `rootfs.S` | 生成并嵌入 Minix v1 镜像 |
| 用户程序 | `user/` | crt0/shell/libc 封装/测试 |

### 1.1 引导模块（boot/head.s）

**它是干什么的**：CPU 上电后从 `0x80000000` 执行的第一段代码，负责把
内核“铺好床”再交给 C 语言入口 `main()`。

**原版 x86 对应物**：x86 的 `boot/bootsect.s` + `setup.s`，需要从软盘
加载、切到保护模式、建 GDT/IDT、开分页。RISC-V 版大幅简化。

**本移植做了什么**：

```asm
_start:
	la t0, _bss_start
	la t1, _bss_end
	...           # 1. 清零 .bss（C 语言要求全局变量初值为 0）
	la sp, _stack_top
	csrw mscratch, sp    # 2. 引导栈 + mscratch（trap 换栈用）
	li t0, -1
	csrw pmpaddr0, t0
	li t0, 0x0f
	csrw pmpcfg0, t0     # 3. PMP：允许 S/U 模式访问全部内存
	sfence.vma
	call main            # 4. 进 C
```

**初学者必懂的点**：

- **为什么必须配置 PMP**：RISC-V 规定未匹配任何 PMP 条目的 S/U 模式
  访问一律拒绝。QEMU 上不配 PMP，mret 到用户态第一条指令就
  `fault_fetch`（表现为莫名跳 0 死循环）。这是 RISC-V 裸机最常见的坑。
- **mscratch 是什么**：M-mode 的“备用寄存器”。用户态 trap 进来时
  用它换出用户栈、换入内核栈（见 1.2）。
- **QEMU 从哪启动**：`-bios none -kernel kernel.elf`，QEMU 直接把
  镜像加载到 0x80000000，M-mode 复位入口就是 `_start`，不需要 SBI。

### 1.2 陷阱与上下文切换（kernel/trap.S）

**它是干什么的**：所有中断/异常的统一入口（`mtvec = trap_entry`）、
统一返回（`ret_from_trap`）、以及任务切换（`switch_to`）。

**原版 x86 对应物**：x86 有硬件自动压栈 + `kernel/system_call.s` 的
保存/恢复；任务切换用 TSS + `ljmp`。RISC-V 没有这些，全部软件完成。

**本移植的 trapframe（140 字节）**：

```
偏移   内容
0      mstatus      （mret 恢复中断状态/特权级用）
4      mepc         （mret 返回地址）
8       x1(ra) … 128 x31(t6)（32 个通用寄存器）
132    mcause       （异常原因）
136    from_user    （1=来自用户态）
```

**关键设计**：

- **用户态 trap**：`csrrw sp, mscratch, sp` 换到内核栈顶，保存全部
  寄存器；返回时恢复寄存器并 mret。
- **内核态 trap**：不换栈，在当前 sp 处压帧——这样嵌套 trap
  （比如系统调用执行中被定时器打断）不会互相踩踏。
- **switch_to**：软件保存 ra/sp/s0-s11 到 task_struct，加载下一个
  任务，并设置 `mscratch = 新任务内核栈顶`。

**初学者必懂的点**：

- 每进一次 trap 保存一份完整现场，返回时**逐寄存器恢复**，一个都不能少
  ——漏一个就是“莫名崩溃”。
- **trap 入口用 t0/t1 做临时寄存器**是刻意为之，但也因此用户态 ecall
  后 t0/t1 会变垃圾值，必须靠用户态 clobber 声明兜底（见 2.3）。

### 1.3 异常分发（kernel/traps.c）

**它是干什么的**：`trap_handler(tf)` 拿着保存好的 trapframe，按
`mcause` 决定怎么办：

```c
if ((cause & 0x80000000) && (cause & 0xff) == 7)
	→ 定时器：jiffies++、重设 CLINT、do_timer()
case 8 / 11
	→ ecall（用户态 / M 态系统调用）：mepc += 4，查 sys_call_table
case 12 / 15
	→ 页错误：page_fault_handler()
default
	→ 内核态异常：打印并 panic
```

**原版 x86 对应物**：x86 的 `kernel/traps.c` + IDT 中断门，每个中断号
一个入口。RISC-V 合并成单一入口 + mcause 分发。

**初学者必懂的点**：

- ecall 后**必须 `mepc += 4`**，否则 mret 会重新执行 ecall 死循环。
- mcause 的定时器值是 `0x80000007`（高位是“中断”标志，低 8 位是码），
  页错误/取指错误等同步异常是 12/13/15 这类小数字——新手容易只比对
  低 8 位或只比对数值而判断错。

### 1.4 时钟模块（kernel/sched.c + CLINT）

**它是干什么的**：提供 100Hz 的“心跳”，驱动进程调度、
`jiffies` 时钟、`alarm()` 超时。

**原版 x86 对应物**：8253/8254 PIT 定时器 + 8259A 中断控制器，
中断 0x20。RISC-V 用 CLINT 的 mtime/mtimecmp。

**本移植实现**：

```c
/* traps.c 定时器分支 */
CLINT_MTIMECMP = CLINT_MTIME + TIMER_INTERVAL;   /* 重设下一次中断 */
do_timer(from_user);

/* sched.c */
void do_timer(long cpl) {
	jiffies++;                       /* 时钟节拍（在陷阱入口递增） */
	if ((--current->counter) > 0) return;
	current->counter = 0;
	if (!cpl) return;
	current->counter = current->priority;
	schedule();                      /* 时间片耗尽，切换任务 */
}
```

**初学者必懂的点**：

- `jiffies` 的递增位置容易漏：x86 在汇编入口做，移植到 C 后如果不加，
  `alarm()`/`times()` 永远不触发（见 2.4）。
- `mtimecmp` 必须**每次中断都重设**，否则只响一次。

### 1.5 控制台模块（kernel/chr_drv/console.c）

**它是干什么的**：读写 QEMU `virt` 机器 0x10000000 处的 16550 UART，
承担 printk、终端输入输出。

**原版 x86 对应物**：EGA/VGA 文本显存 + 键盘中断。RISC-V 换串口，
输入也从“中断驱动”改成“轮询”。

**本移植实现**：

```c
void uart_putc(char c) {
	while (!(inb(UART_LSR) & 0x20)) ;   /* 等发送寄存器空 */
	outb(c, UART_THR);
}
int uart_getc(void) {
	if (inb(UART_LSR) & 0x01) return inb(UART_RBR) & 0xff;
	return -1;                          /* 无字符 */
}
```

**初学者必懂的点**：

- 输出是**忙等轮询**，没有“往寄存器一写就完事”这回事，忘了等 LSR
  就会丢字符。
- 输入没有中断，只能由 `tty_read` 里的 `con_poll()` 主动去读——
  如果等待路径不轮询，就永远等不到字符（见 2.11 的“单字符卡死”）。
- `con_write`/`con_poll` 的 cli/sti 要支持**嵌套**（见 2.10）。

### 1.6 块设备：ramdisk（kernel/blk_drv/ramdisk.c）

**它是干什么的**：把嵌入内核的 rootfs 镜像当成一个块设备
（主设备号 1），供文件系统层 `bread()/ll_rw_block()` 读写。

**原版 x86 对应物**：软盘（HD）驱动，要从真实磁盘搬扇区。

**本移植实现**：块 N 的扇区就是镜像里的偏移，读/写都是 memcpy：

```c
void do_rd_request(void) {
	INIT_REQUEST;
	addr = rd_start + (CURRENT->sector << 9);
	...
	if (CURRENT->cmd == WRITE)
		memcpy(addr, CURRENT->buffer, len);   /* 写回镜像 */
	else
		memcpy(CURRENT->buffer, addr, len);   /* 读 */
}
```

**初学者必懂的点**：

- 这是“内存盘”：**重启即丢**，对它的写会直接改内存里那份镜像。
- 块设备请求的 `sector` 是 512 字节扇区，文件系统按 1024 字节块访问，
  所以 `req->sector = bh->b_blocknr << 1`（一个块=两个扇区）。

### 1.7 内存管理（mm/memory.c + Sv32）

**它是干什么的**：管理物理页（mem_map）、给用户任务建 Sv32 页表、
实现 COW fork、以及内核态访问用户内存的地址翻译。

**原版 x86 对应物**：x86 两级页表 + 段寄存器。RISC-V 用 Sv32
（两级，10+10 位页索引，页大小 4KB）。

**本移植的关键设计**：

- 内核跑在 M-mode（**不开地址翻译**），用户跑在 U-mode（开 Sv32）；
- 用户任务各有一份 pgdir，PTE 用 `PTE_USER_RWX`（V|R|W|X|U|A|D）；
- fork 时复制页目录并清 W 位实现 COW，写时 `un_wp_page()` 复制；
- 内核读用户指针走 `translate_user()`：手工查当前任务页表拿物理地址，
  失败返回 -1。

**初学者必懂的点**：

- **PTE 编码必须符合 Sv32**：PPN 在 bits[31:10]，即
  `pte = (phys >> 12) << 10 | flags`。把物理地址直接塞 PTE 是“自洽但
  硬件不认”的典型错误（见 2.1）。
- 内核在 M-mode 下**不能直接解引用用户指针**，必须查表翻译——漏了
  就会读到物理地址上并不存在的“用户内存”。

### 1.8 系统调用 ABI

**它是干什么的**：规定用户程序怎么“求内核办事”。

**原版 x86**：`int 0x80`，调用号放 eax。**RISC-V**：`ecall`，
调用号放 a7，参数 a0-a2，返回值 a0。

**本移植实现**（用户态宏，`include/unistd.h`）：

```c
#define _syscall1(type,name,atype,a) \
type name(atype a) { \
	register long __a7 __asm__("a7") = __NR_##name; \
	register long __a0 __asm__("a0") = (long)(a); \
	__asm__ volatile ("ecall" : "+r"(__a7), "+r"(__a0) \
		:: "memory", "t0", "t1"); \
	...
}
```

**初学者必懂的点**：

- clobber 列表里的 `"t0","t1"` 是移植后**必须加**的（见 2.3）——
  不加的话 gcc 会以为 ecall 之后 t0/t1 还是原值，实际已被内核 trap
  入口改掉，程序就“抽风”。
- 系统调用号从 0 开始排（`setup=0, exit=1, fork=2, ...`），一共 73 个，
  和 x86 版保持一致，方便对照原版文档。

### 1.9 链接脚本（kernel.ld）

**它是干什么的**：规定内核镜像里各段放哪、`_kernel_end` 在哪，
决定缓冲区/内存分配从哪里开始。

**关键布局**：

```
0x80000000  .text  .rodata  .data
            .rootfs            ← 2MB 根文件系统镜像
            .bss
0x8021d000  _kernel_end（对齐 4KB）
```

**初学者必懂的点**：

- `end = _kernel_end` 被 `buffer_init()` 拿来当缓冲区起点，
  `PAGE_ALIGN(_kernel_end) + 1MB` 作为 `main_memory_start`，是
  `mem_map` 开始分配的位置——改布局就要同步改这两处。
- `.rootfs` 必须用 `KEEP(*(.rootfs))` 且放在 `.bss` 之前，否则会被
  gc 掉或布局错乱。

### 1.10 rootfs 生成（tools/mkfs.c + rootfs.S）

**它是干什么的**：在**宿主机**上把用户程序打包成 Minix v1 文件系统
镜像，再嵌进内核。

**本移植实现**：

```sh
tools/mkfs rootfs.img user/sh.elf user/hello.elf user/t_*.elf
printf '.section .rootfs,"a",@progbits\n.incbin "rootfs.img"\n' > rootfs.S
```

镜像布局：块 0 引导块（空）、块 1 超级块、块 2/3 inode/zone 位图、
块 4+ inode 表、之后是数据区。

**初学者必懂的点**：

- **嵌入必须用 `.incbin`，不要用 objcopy**：objcopy 对未初始化区域
  “写 0”，会破坏镜像里实际有数据的部分。
- Minix v1 的约定要两端对齐：**`i_zone[]` 存块号**（区 N = 块
  firstdata+N-1），zmap 存区号。mkfs 和内核必须一致（见 2.6 相关）。

### 1.11 用户程序（user/）

**它是干什么的**：ELF32 用户态程序：入口 crt0、libc 封装、shell、
测试程序。

**本移植实现**：

- `user/crt0.S`：取 argc/argv/envp → 跳 main → 返回后 _exit。
- `user/sh.c`：内置 `cd/pwd/echo/ls/exit`，其余按 `/bin/<cmd>` 执行；
  支持多行粘贴与退格（DEL/BS）。
- `user/uprint.c`：测试用的极简 printf。
- `user/t_*.c`：功能/压力测试（详见测试指南）。

**初学者必懂的点**：

- 用户程序用 `#define __LIBRARY__` + `#include <unistd.h>` 拿内联
  系统调用宏，链接时只带 `_exit.o` 和 `errno.o`，避免和 lib 桩重复定义。
- 虚拟地址 0x10000 起（可执行段），栈顶 0x7fe00000——`exec` 按
  ELF 的 PT_LOAD 段建页表。

## 二、对原版逻辑的修改

### 1. Sv32 PTE 编码（`include/linux/mm.h`、`mm/memory.c`）

- **原版**：x86 页表项格式。
- **问题**：早期移植把物理页地址直接放进 PTE（`phys | flags`），内核自查
  页表自洽，但 CPU 硬件翻译把 PPN 字段（Sv32 占 bits[31:10]）解析成错误
  值 → 首次进入用户态取指即 `exec_page_fault` 死循环。
- **修改**：统一按 Sv32 编码/解码：

```c
/* 编码：pte = (phys >> 12) << 10 | flags */
static inline unsigned long phys_ppn(unsigned long phys)
{
	return (phys >> 12) << PTE_PPN_SHIFT;
}
/* 解码：phys = ((pte >> 10) & PTE_PPN_MASK) << 12 */
static inline unsigned long pte_phys(unsigned long pte)
{
	return ((pte >> PTE_PPN_SHIFT) & PTE_PPN_MASK) << 12;
}
```

### 2. PMP 配置（`boot/head.s`）

- **问题**：QEMU 在未配置 PMP 时，S/U 模式所有访存均失败
  （mret 到用户态第一条指令就 `fault_fetch`）。
- **修改**：启动早期配置 `pmpaddr0 = -1`、`pmpcfg0 = 0x0f`
  （TOR，R|W|X，覆盖全部地址）。

### 3. 用户态 ecall 声明 t0/t1 clobber（`include/unistd.h`、`lib/open.c`、
    `lib/_exit.c`、`user/uprint.c`）

- **原版**：x86 `int 0x80` 只改 eax；内联汇编 clobber 只列返回寄存器。
- **问题**：本移植的 M-mode trap 入口用 t0/t1 做临时寄存器，每次 ecall 后
  用户态 t0/t1 变垃圾值（t1 变成 mepc）。gcc 认为 ecall 只改 a7/a0/a1/a2，
  继续在调用间使用 t0/t1 → 表现是输出每行只打一个字符、逻辑错乱。
- **修改**：`_syscall0/1/2/3` 宏与手工 ecall 的 clobber 列表加 `"t0","t1"`，
  由编译器保存/恢复。

### 4. jiffies 递增（`kernel/traps.c`）

- **原版**：x86 在汇编定时器入口递增 `jiffies`。
- **问题**：移植后定时器走 C 路径，漏了 `jiffies++` → `alarm()`/`times()`
  永远不触发（SIGALRM 测试卡死）。
- **修改**：定时器分支（mcause=0x80000007）里先 `jiffies++` 再重设
  CLINT_MTIMECMP、调 `do_timer()`。

### 5. clear_bit 返回语义（`fs/bitmap.c`）

- **原版**：x86 `btrl + setnb` —— 位**原本已清除**时返回 1。
- **问题**：移植的 C 版返回“原本是否置位”（1=成功清除），与调用方
  判断相反 → 首次正常释放 inode/block 被误判为 double-free，直接
  `Kernel panic: free_block: bit already cleared`。
- **修改**：`return old ? 0 : 1;`。

### 6. mount_root 位图只读统计（`fs/super.c`）

- **原版**：统计空闲 inode/zone 时用 `set_bit` 遍历位图，会把所有空闲位
  标成已用。
- **问题**：首次创建文件即 ENOSPC（inode/zone 位图全 1）。
- **修改**：新增只读 `test_bit`，统计时不改动位图。

### 7. sys_creat 补 O_WRONLY（`fs/open.c`）

- **原版**：`sys_open(pathname, O_CREAT | O_TRUNC, mode)`，缺少
  `O_WRONLY`（x86 原版同样缺，但 open_namei 内部有兜底）。
- **修改**：补全为 `O_CREAT | O_TRUNC | O_WRONLY`，语义完整。

### 8. exec 设置 end_code（`fs/exec.c`）

- **原版**：`do_execve` 只设置 start_code/end_data/brk。
- **问题**：`end_code` 恒为 0 → `sys_brk` 的边界判断失效，
  `brk(0)` 会把堆清到 0（堆分配测试失败）。
- **修改**：加载段时同步维护 `end_code = max(end_code, vaddr+memsz)`。

### 9. fork 不再重复 mepc += 4（`kernel/fork.c`）

- **原版**：`copy_process` 复制 trapframe 后 `tf->mepc += 4`。
- **问题**：本移植的 `trap_handler` 处理 ecall 时已 `mepc += 4`，再
  加一次会让子进程从错误 PC 恢复（跳过 ecall 后续指令，行为随机错乱）。
- **修改**：删掉 `copy_process` 里的 `tf->mepc += 4`。

### 10. 控制台 cli/sti 嵌套安全（`kernel/chr_drv/console.c`、
     `include/asm/system.h`）

- **原版**：`con_write`/`con_poll` 内部 `cli(); ...; sti();`。
- **问题**：`con_poll` 已 `cli()` 时，内部 `copy_to_cooked → con_write`
  的 `sti()` 会提前重开中断 → 定时器与 UART 队列竞态，长时间输出后
  丢字符甚至卡死。
- **修改**：新增 `save_flags()/restore_flags()`，按进入时的中断标志恢复，
  支持嵌套。

### 11. tty_read 轮询等待整行（`kernel/chr_drv/tty_io.c`）

- **原版**：`sleep_if_empty` 只睡眠，由控制台中断唤醒。
- **问题**：移植改为 busy-wait 轮询后，`sleep_if_empty` 只在队列
  **完全为空**时轮询 UART；当“已输入字符但还没凑成整行”（canonical
  等回车）时直接返回，主循环自旋不读 UART → **输入一个字符就卡死**。
- **修改**：tty_read 的等待改成内联轮询循环，`con_poll()` 直到
  队列非空且 canonical 下 data>0（整行完成）才继续。

### 12. 退格支持 BS 与 ECHOE（`kernel/chr_drv/tty_io.c`）

- **原版**：ERASE 只认 DEL(0x7f)，回显 DEL 字符，termios 无 ECHOE。
- **问题**：部分终端退格发 BS(0x08)；且不回显 `\b \b` 导致屏幕上
  字符不擦除，看起来“退格不正常”。
- **修改**：`c == ERASE_CHAR || c == 8` 都按删除处理；控制台 termios
  加 `ECHOE`，删除时回显 `\b \b`（控制字符回显两套）。

### 13. buffer 哈希链 NULL 保护（`fs/buffer.c`）

- **原版**：`remove_from_queues` 直接 `bh->b_next->b_prev = ...`，x86 上
  第 0 页被映射掩盖了 NULL 解引用。
- **问题**：RISC-V 上 NULL 解引用即 fault。
- **修改**：`insert_into_queues`/`remove_from_queues` 对 `b_next`/`b_prev`
  判空。

### 14. do_div 用 rv32 硬件除法（`kernel/vsprintf.c`）

- **原版**：x86 32 位除法内联汇编。
- **修改**：rv32imac 自带 `div`/`rem` 指令，`do_div(n, base)` 直接用
  硬件除法，避免软除法实现。

### 15. stdarg 换 __builtin_va_list（`include/stdarg.h`）

- **原版**：x86 栈传参的 va_list 布局。
- **问题**：rv32 按寄存器传参，x86 布局不可用。
- **修改**：直接使用编译器内置 `__builtin_va_*`。

### 16. unistd.h 声明块按 __LIBRARY__ 隔离（`include/unistd.h`）

- **原版**：用户态函数声明在所有包含者可见。
- **问题**：测试程序 `#define __LIBRARY__` 用 `_syscallN` 宏内联定义
  同名函数时，与 unistd.h 的 extern 声明类型冲突（如 `off_t` vs `int`）。
- **修改**：声明块用 `#ifndef __LIBRARY__` 包裹，`__LIBRARY__` 使用者
  只看到宏与调用号。

### 17. sys_call_table 位置与数量（`kernel/sys.c`、`include/linux/sys.h`）

- **原版**：调用表在 `kernel/system_call.s` 附近。
- **修改**：73 项 `sys_call_table[]` 移到 `kernel/sys.c`，
  `include/linux/sys.h` 只留 extern 声明；`ftime/ptrace/acct` 等
  返回 -ENOSYS 的桩函数补齐。

### 18. init/main.c 启动流程调整

- 去掉 x86 特定初始化（8259A、软驱、键盘、硬盘等）。
- `ROOT_DEV = 0x0101`（ramdisk：主 1 次 1），挂载根文件系统。
- 定时器用 CLINT；`startup_time = 0`（无 RTC）。
- 保留 `kernel_thread(init)` 结构：init 打开 /dev/tty0 → spawn shell。

### 19. shell 内置命令与输入处理（`user/sh.c`，用户态新增）

- 内置 `cd/pwd/echo/ls/exit`；其余按 `/bin/<cmd>` 执行。
- 支持多行粘贴（一次 read 分多条执行）、参数 argv 清零（避免无参命令
  读到栈垃圾）、退格（DEL/BS）。

### 20. 测试程序（`user/t_*.c`，用户态新增）

- `t_up`（printf 回归）、`t_fork`、`t_cow`、`t_fs`、`t_pipe`、
  `t_sig`、`t_sched`、`t_stress`（综合五阶段压力）。
- `t_fp`：浮点回归（rv32imafdc/ilp32d 编译），验证 FP 上下文跨 trap
  保存正确（收敛序列输出固定 2.0）。
- 详见[测试指南](测试指南.md)。

### 21. 浮点上下文保存（`kernel/trap.S`、`include/linux/sched.h`、
    `fs/exec.c`）

- **原版**：x86 用数学协处理器（last_task_used_math 懒加载）。
- **问题**：RV32D 下 double 占完整 64 位 f 寄存器槽；若 trap 不保存
  浮点状态，用户浮点程序在每次中断/系统调用后结果随机错乱；若用
  32 位 fsw/flw 保存，则只存低 32 位、高 32 位残留垃圾。
- **修改**：
  - 工具链升级为 `rv32imafdc_zicsr_zifencei/ilp32d`（内核同样，便于
    trap.S 使用 FP 指令）；
  - trapframe 扩展 f[32]（64 位）+ fcsr，TF_SIZE=400；
  - trap 入口置 mstatus.FS=Dirty 后，用 `fsd/fld` 保存/恢复 f0-f31
    与 fcsr；
  - exec 初始 trapframe `mstatus = 0x6088`（含 FS）。

## 排查速查

| 现象 | 对应修改点 |
|---|---|
| 进用户态第一条指令反复 fault | 1（PTE 编码）、2（PMP） |
| 每行只打一个字符 | 3（ecall t0/t1 clobber） |
| alarm 不触发 / 测试卡死 | 4（jiffies++） |
| FS 首次创建文件 ENOSPC / double-free panic | 5、6（位图语义） |
| brk 堆分配异常 | 8（end_code） |
| fork 后子进程行为错乱 | 9（mepc） |
| 长时间输出丢字/卡死 | 10（cli/sti 嵌套） |
| 输入一个字符卡死 | 11（tty_read 轮询整行） |
| 退格不擦字 / 不生效 | 12（BS + ECHOE） |
| 内核空指针 crash | 13（buffer 链 NULL 保护） |
