# Linux 0.11 for RISC-V — 移植设计文档

本文档描述 Linux 0.11（1991 年 Linus 的经典内核）向 RISC-V（rv32）移植的
整体设计、关键实现和移植过程中踩过的坑。源码位于本仓库 `linux-0.11/`，
构建产物为 `kernel.elf`，运行于 QEMU `virt` 机器（无 OpenSBI，M-mode 裸机）。

## 1. 概述

| 项目 | 内容 |
|---|---|
| 内核基线 | Linux 0.11（kernel.org Historic/old-versions） |
| 架构 | RISC-V 32 位（rv32imac_zicsr_zifencei / ilp32） |
| 运行环境 | QEMU 8.2 `-M virt -m 128M -bios none -kernel kernel.elf` |
| 特权级 | 内核/全部异常处理在 M-mode；用户态 U-mode（Sv32 分页） |
| 存储 | 128MB 物理内存（0x80000000 起）；2MB Minix v1 ramdisk rootfs |
| 外设 | 16550 UART（0x10000000）轮询控制台；CLINT 定时器 |

## 2. 构建与运行

依赖：

- `riscv64-unknown-elf-gcc`（需 rv32imac_zicsr_zifencei/ilp32 多库）
- `qemu-system-riscv32`
- `gdb-multiarch`（可选，调试用）

```sh
make -j8      # 生成 kernel.elf（内含 rootfs）
make run      # qemu-system-riscv32 -M virt -m 128M -bios none \
              #   -kernel kernel.elf -nographic -no-reboot
```

## 3. 启动流程

```
QEMU 复位（M-mode, pc=0x80000000）
  └─ boot/head.s
       ├─ 清零 .bss
       ├─ 建立引导栈（_stack_top，.bss 内 16KB）
       ├─ 配置 PMP：pmpaddr0=-1, pmpcfg0=0x0f（TOR, R|W|X）
       │    （QEMU 在无 PMP 条目时禁止 S/U 模式访问，必须配置）
       └─ 跳转 main()
  └─ init/main.c main()
       ├─ rd_init()：登记 ramdisk 块驱动
       ├─ mem_init()：初始化 mem_map（从 buffer_end 之后开始分配）
       ├─ trap_init()：mtvec ← trap_entry
       ├─ sched_init()：使能 CLINT 定时器中断（MTIE）
       ├─ buffer_init()：缓冲区缓存（989 个 1KB buffer）
       ├─ mount_root()：读取并挂载 Minix v1 根文件系统
       ├─ sti()：开中断
       └─ kernel_thread(init)；进入 task0 的 for(;;) pause() 空闲循环
  └─ init 内核线程
       ├─ open("/dev/tty0") dup dup（标准输入输出）
       ├─ kernel_thread(shell)：创建 shell 内核线程
       └─ shell 执行 execve("/bin/sh") 进入用户态
```

## 4. 内存管理（Sv32）

### 4.1 物理内存布局

```
0x8000_0000  kernel 镜像（.text/.rodata/.data/.rootfs/.bss）
0x8021_d000  _kernel_end
             buffer 头 + buffer 数据（约 1MB，向 buffer_end 递减放置）
0x8031_d000  buffer_end = main_memory_start（mem_map 从此处开始分配）
             get_free_page() 返回的页（task 结构、页表、用户页）
0x8800_0000  RAM_END（128MB）
```

### 4.2 Sv32 页表

- 每个用户任务拥有独立页目录（pgdir），内核在 M-mode 运行（bare，无翻译）。
- 用户虚拟地址范围 [0, USER_LIMIT=0x80000000)，内核物理地址 0x80000000+。
- 用户页用 `PTE_USER_RWX`（V|R|W|X|U|A|D）映射；写时复制时清 W 位。

**关键：Sv32 PTE 编码。** PPN 字段占 bits[31:10]，必须按
`pte = (phys >> 12) << 10 | flags` 编码；解码用 `pte_phys()`：

```c
static inline unsigned long pte_phys(unsigned long pte)
{
	return ((pte >> PTE_PPN_SHIFT) & PTE_PPN_MASK) << 12;
}
```

早期实现把物理页地址直接塞进 PTE（`phys | flags`），内核自查页表时自洽、
但 CPU 硬件翻译时把 PPN 解析成错误值，导致首次进入用户态取指即 fault
（`exec_page_fault` 死循环）。这是本移植最重要的一个坑。

### 4.3 用户内存访问

内核 M-mode 不能直接解引用用户虚拟地址，统一走
`translate_user()`（查当前任务页表返回物理地址），失败返回 -1，
`get_fs_byte/put_fs_long` 等封装在失败时调用 `uaccess_fault()`。

## 5. 陷阱与上下文切换

### 5.1 trap_entry / ret_from_trap（kernel/trap.S）

所有异常/中断留在 M-mode，`mtvec = trap_entry`。trapframe 140 字节：

```
0   mstatus
4   mepc
8   x1(ra) … 128 x31(t6)
132 mcause
136 from_user
```

- **用户态 trap**：`csrrw sp, mscratch, sp` 换到内核栈顶，保存全寄存器。
- **内核态 trap**：不换栈，在当前位置压帧（可嵌套）。
- `ret_from_trap` 恢复寄存器、设置 satp（回到用户态时生效）、恢复
  mscratch = 帧 + TF_SIZE（用户态即内核栈顶）后 mret。

**关键坑：trap 入口用 t0/t1 做临时寄存器。** M-mode 入口在保存 x5/x6
之前就把 mstatus/mepc 读进 t0/t1，导致用户态的 t0/t1 在每次 ecall 后
变成垃圾值（t1 变成 mepc）。gcc 认为 ecall 只改 a7/a0/a1/a2，会在调用
前后继续使用 t0/t1，表现就是输出每行只打一个字符、逻辑错乱。

修复方式：用户态所有 ecall 内联汇编把 `t0/t1` 声明为 clobber
（见 `include/unistd.h` 的 `_syscallN` 宏），由编译器保存/恢复。

### 5.2 任务切换

- `switch_to()`：软件上下文切换，保存 ra/sp/s0-s11 到 task_struct 的
  kctx 字段（偏移 0..52），并设置 `mscratch = 新任务内核栈顶`。
- `kernel_thread()`：创建内核态任务（init、shell 初始阶段）。
- `copy_process()`：fork 用户任务，复制 trapframe 与页表（COW）。

**坑：fork 的 mepc 处理。** `trap_handler` 处理 ecall 时已
`tf->mepc += 4`，fork 复制 trapframe 时不能再加一次，否则子进程从
错误 PC 恢复（行为随机错乱）。

## 6. 系统调用

- 约定：`a7` 为调用号，`a0-a2` 为参数，返回值在 `a0`。
- 73 个系统调用与 0.11 对齐（`kernel/sys.c` 的 `sys_call_table`）。
- `trap_handler` 对 cause 8/11（U/M 模式 ecall）统一分发；ecall 后
  `mepc += 4`。
- 用户态封装：`include/unistd.h` 的 `_syscall0/1/2/3` 宏 + `lib/*.c`。

## 7. 定时器与调度

- CLINT 定时器，`HZ=100`；`trap_handler` 收到 mcause=0x80000007 时
  重设 CLINT_MTIMECMP 并调用 `do_timer(from_user)`。
- **坑：jiffies 递增。** x86 版在汇编定时器入口递增 jiffies，移植后
  漏掉了，导致 `alarm()`/`times()` 永远不触发。修复：在定时器分支
  `jiffies++`。
- `do_timer` 递减当前任务 counter，耗尽后 schedule()；schedule() 里
  检查所有任务的 alarm，到点发 SIGALRM 并把有信号的
  TASK_INTERRUPTIBLE 任务唤醒。

## 8. 文件系统

### 8.1 Minix v1 + ramdisk

- `tools/mkfs.c` 生成 2MB Minix v1 镜像，经 `rootfs.S` `.incbin`
  嵌入内核 `.rootfs` 段。
- 布局：块0 引导块、块1 超级块、块2/3 inode/zone 位图、块4+ inode 表、
  之后为数据区。
- **约定**：`i_zone[]` 存**块号**（区 N = 块 firstdata+N-1），zmap 存区号。
- **坑：rootfs 必须用 `.incbin`**，不要改用 objcopy 嵌入——objcopy
  会“写 0”破坏数据。

### 8.2 移植修正

| 问题 | 说明 |
|---|---|
| `clear_bit` 返回值 | x86 `btrl+setnb` 在“位原本已清除”时返回 1；C 版需 `return old ? 0 : 1` |
| mount_root 统计 | 原版用 `set_bit` 计数会把整块位图标成已用，改为只读 `test_bit` |
| `sys_creat` | 原版 `O_CREAT|O_TRUNC` 缺 `O_WRONLY`，补上 |
| exec `end_code` | 未设置导致 `brk(0)` 边界错误，补 `end_code = end_data` |

## 9. 控制台（16550 UART）

- 0x10000000 处的 16550；输出轮询 LSR/THR，输入在 tty_read 时轮询
  （`con_poll()`），无输入中断。
- `con_write`/`con_poll` 使用 `save_flags()/restore_flags()` 保存/恢复
  中断标志，避免嵌套 cli/sti 不平衡导致的中断提前开启（长时间输出后
  丢字符、卡死）。
- 终端模式：`ICRNL, OPOST|ONLCR, ISIG|ICANON|ECHO|ECHOE|ECHOCTL|ECHOKE`；
  退格同时支持 DEL(0x7f) 和 BS(0x08)，开启 ECHOE 后回显 `\b \b`
  在屏幕上真正擦除字符。

## 10. 用户程序与 shell

- ELF32 rv32 静态链接；入口 0x10000，栈顶 0x7fe00000。
- `user/crt0.S`：取 argc/argv/envp，跳 main，返回后 _exit。
- `user/sh.c`：内置 `cd/pwd/echo/ls/exit`，其余命令按 `/bin/<cmd>`
  查找执行；支持多行粘贴、退格。
- `user/uprint.c`：测试用的极简 printf（%s %c %d %u %x %lx）。

```

```

## 12. 已知限制与后续方向

- 单 hart、无换页、无浮点；`ftime/ptrace/acct` 等返回 -ENOSYS。
- UART 轮询输入，无输入中断；终端输入需 shell 处于 read 轮询状态。
- rootfs 为内存盘，重启后修改丢失。
- 后续可做：更多内置/外部命令（cat/mkdir/rm）、写 ramdisk 之外的
  块设备、更完整信号/作业控制、SMP。
