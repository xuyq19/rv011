# Linux 0.11 移植到 RISC-V —— 一步一步怎么做的

本文记录把官方 Linux 0.11（1991）移植到 RISC-V（rv32）并跑在 QEMU
`virt` 机器上的完整过程。按阶段写：**每阶段要做什么、怎么验证、踩了什么
坑**。适合想自己复现一遍，或者对照学习裸机 RISC-V + 老内核的人。

最终形态：无 OpenSBI，内核在 M-mode 裸机启动；用户态 U-mode 用 Sv32
分页；支持硬件浮点（rv32imafdc）；带 shell 与全套测试；GitHub Actions
自动构建、冒烟、发 Release。

---

## 阶段 0：准备环境

需要三样东西：

- `riscv64-unknown-elf-gcc`（带 rv32 多库；Ubuntu 的
  `gcc-riscv64-unknown-elf` 13.2.0 即可）；
- `qemu-system-riscv32`；
- `gdb-multiarch`（调试用，强烈建议）。

拿到官方源码（仓库基线 `c39fe67`）：

```sh
git clone <本仓库>
git checkout c39fe67        # 官方 Linux 0.11
```

先用一句话验证工具链 rv32 可用：

```sh
echo 'int main(void){return 0;}' > t.c
riscv64-unknown-elf-gcc -march=rv32imafdc_zicsr_zifencei -mabi=ilp32d -c t.c
```

> 坑：多库缺 rv32 时，`-march=rv32...` 会直接报错找不到 multilib。

## 阶段 1：最小启动 —— 先让 printk 有输出

目标：QEMU 启动后能在串口看到一行字。这是整个移植的第一个里程碑。

### 1.1 链接脚本（kernel.ld）

规定镜像布局：`.text/.rodata/.data/.bss` 从 `0x80000000` 开始，
`_kernel_end` 对齐 4KB（后面缓冲区、内存分配都从它算起）。

### 1.2 启动入口（boot/head.s）

QEMU `-bios none` 下 CPU 复位到 `0x80000000`（M-mode）。head.s 做四件事：

1. 清零 `.bss`（C 语言依赖）；
2. 建引导栈（.bss 里 16KB，`_stack_top`）；
3. **配置 PMP**：`pmpaddr0=-1, pmpcfg0=0x0f`；
4. `call main`。

> 坑：**不配 PMP，S/U 模式访问全挂**。第一次 mret 到用户态就
> `fault_fetch` 死循环。这是 RISC-V 裸机第一个经典坑。

### 1.3 串口（console.c + uart_init）

QEMU `virt` 的 16550 UART 在 `0x10000000`。先做轮询输出：

```c
void uart_putc(char c) {
	while (!(inb(UART_LSR) & 0x20)) ;   /* 等 THR 空 */
	outb(c, UART_THR);
}
```

把 `printk` 接到它，`main()` 里 `printk("hello\n")`，QEMU 能看到即通过。

> 验证：`timeout 5 qemu-system-riscv32 -M virt -m 128M -bios none \
> -kernel kernel.elf -nographic -no-reboot` 出现输出。

## 阶段 2：trap 与定时器

目标：中断/异常有统一入口，定时器能驱动 `jiffies` 和调度。

### 2.1 trap 入口（kernel/trap.S）

- `mtvec = trap_entry`，所有异常/中断进同一入口；
- 用户态 trap：`csrrw sp, mscratch, sp` 换到内核栈顶，保存全寄存器
  （trapframe）；
- 内核态 trap：不换栈，在当前 sp 压帧（可嵌套）；
- `ret_from_trap` 恢复寄存器、设置 satp、mret。

trapframe 布局（最终 400 字节）：

```
0   mstatus   4   mepc   8..128  x1..x31
132 mcause    136 from_user
140 f0..f31（64 位）    396 fcsr
```

> 坑 1：**trap 入口用 t0/t1 做临时寄存器**（读 mstatus/mepc），会破坏
> 用户态 t0/t1。解决：用户态所有 ecall 内联汇编把 `t0,t1` 声明为
> clobber（见 `include/unistd.h` 的 `_syscallN`）。
>
> 坑 2：**嵌套 trap 的帧位置**。内核态 trap 若换到栈顶压帧，会被更深的
> 定时器中断覆盖；内核态必须在当前 sp 压帧。

### 2.2 定时器（CLINT）

- `sched_init()` 开 MTIE，`trap_handler` 收到 mcause=0x80000007 时
  重设 `CLINT_MTIMECMP`，调 `do_timer()`；
- **jiffies++ 必须在定时器路径**（x86 在汇编里做，C 移植容易漏），
  否则 `alarm()/times()` 永不触发。

> 验证：`times()` 返回值随时间增长。

## 阶段 3：内存管理与 Sv32 页表

目标：物理页分配（mem_map）、用户任务 Sv32 页目录、内核访问用户内存。

### 3.1 内存布局

```
0x80000000  kernel 镜像
0x8021d000  _kernel_end → buffer 区（约 1MB）
0x8031d000  main_memory_start → mem_map 从这里分配（task、页表、用户页）
```

### 3.2 Sv32 页表

每个用户任务独立 pgdir，PTE 用 `PTE_USER_RWX`；内核 M-mode 不开翻译，
访问用户内存靠 `translate_user()` 手工查表。

> 坑：**PTE 编码必须是 Sv32 格式**——PPN 占 bits[31:10]，
> `pte = (phys >> 12) << 10 | flags`。把物理地址直接塞 PTE，内核自查
> 自洽但硬件翻译不认，首次进用户态取指即 `exec_page_fault` 死循环。
> 这是本移植调试最久的一个坑。

## 阶段 4：系统调用

约定：`a7` 调用号（0-72，与 0.11 一致），`a0-a2` 参数，返回 `a0`。

- `trap_handler` 对 ecall（cause 8/11）`mepc += 4` 后查
  `sys_call_table`（73 项，放在 `kernel/sys.c`）；
- 用户态封装：`_syscall0/1/2/3` 宏（记得 clobber t0/t1）。

> 验证：实现一个 `getpid` 或 `write`，用户程序能调通。

## 阶段 5：文件系统与 rootfs

目标：根文件系统能挂载、能读文件（后面 exec 依赖它）。

### 5.1 生成 Minix v1 镜像（tools/mkfs.c）

在**宿主机**上把用户程序打包成 2MB Minix v1 镜像：

```
块0 引导块（空）  块1 超级块  块2/3 inode/zone 位图
块4+ inode 表    之后数据区
```

约定两端必须一致：**i_zone[] 存块号**（区 N = 块 firstdata+N-1），
zmap 存区号。

### 5.2 嵌入内核（rootfs.S）

```asm
.section .rootfs,"a",@progbits
.incbin "rootfs.img"
```

> 坑：**必须用 .incbin，不要用 objcopy 把镜像转成目标文件**——objcopy
> 会“写 0”破坏数据。

### 5.3 块设备（ramdisk.c）

块 N 的扇区 = `rd_start + N*1024`，读写就是 memcpy。文件系统层的
`bread()` 通过它拿块。

> 坑：位图语义两处（原版 x86 语义）——
> 1. `clear_bit` 返回“原本已清除”（`return old ? 0 : 1`）；
> 2. `mount_root` 统计空闲时不能 `set_bit`（会把位图全标成已用，
>    首次建文件就 ENOSPC）。

> 验证：启动打印 `free blocks / free inodes`，`ls /` 能看到 bin、dev。

## 阶段 6：用户态 —— exec / fork / shell

目标：用户程序能跑起来。

### 6.1 ELF 加载（fs/exec.c）

读 ELF header + PT_LOAD 段，映射到用户地址空间（代码 0x10000 起，
栈顶 0x7fe00000），构造 trapframe 后 mret 进用户态。

> 坑：`do_execve` 要设置 `end_code`，否则 `brk()` 边界错乱
> （brk(0) 会把堆清 0）。

### 6.2 fork（kernel/fork.c）

复制 task_struct + trapframe + 页表（COW）。子进程返回 0 靠
`tf->a0 = 0`。

> 坑：trap_handler 已对 ecall `mepc += 4`，copy_process **不能再加 4**，
> 否则子进程从错误 PC 恢复。

### 6.3 shell（user/sh.c）

内置 `cd/pwd/echo/ls/exit`，其余按 `/bin/<cmd>` 查找执行。

> 坑：无参命令 `argv[1]` 未初始化会读到栈垃圾；多行粘贴一次 read 返回
> 多行，要逐行处理；`exit` 要走带 `logout` 的退出路径。

> 验证：`sh# t_up`、`sh# ls` 正常。

## 阶段 7：硬件浮点（rv32imafdc）

工具链从 `rv32imac` 升到 `rv32imafdc/ilp32d`，用户程序可用 F/D。

内核侧三件事：

1. trapframe 加 f0-f31（**64 位**）+ fcsr；
2. trap 入口先置 `mstatus.FS=Dirty`（否则 M 态执行浮点指令非法），再用
   `fsd/fld` 保存恢复；
3. exec 初始 trapframe `mstatus = 0x6088`（带 FS）。

> 坑 1：**32 位 fsw/flw 会破坏 64 位 FP 槽**——RV32D 的 double 占完整
> 64 位，只存低 32 位会让高 32 位残留垃圾，浮点结果随机变 NaN。
>
> 坑 2：恢复顺序——`lw x31` 会覆盖 t6（帧指针），浮点恢复必须放在
> 恢复 x30/x31 之前。
>
> 坑 3：trap 保存区里 `csrr fcsr` 不能占用 t0（t0 之后要写
> `TF_FROMUSER`），否则用户态/内核态标志被污染。

> 验证：`t_fp` 收敛序列输出固定 `4000000000000000`（2.0）。

## 阶段 8：打磨 —— 控制台与 tty

启动能跑只是开始，交互体验还需要几处修正：

- **cli/sti 要嵌套安全**：`con_write/con_poll` 用 save_flags/restore_flags
  恢复中断标志，否则嵌套时提前开中断，长时间输出丢字/卡死；
- **tty_read 轮询要等整行**：原 busy-wait 只在队列为空时轮询，输入一个
  字符后（等回车）不轮询就卡死；改为轮询直到 canonical 整行完成；
- **退格**：同时认 DEL(0x7f) 和 BS(0x08)，开 ECHOE 回显 `\b \b`
  真正擦除字符。

## 踩坑速查

| 现象 | 原因 |
|---|---|
| 进用户态第一条指令反复 fault | PTE 编码 / PMP 未配 |
| 每行只打一个字符 | ecall 未声明 t0/t1 clobber |
| alarm 不触发 | jiffies 没递增 |
| 首次建文件 ENOSPC / double-free panic | 位图语义（clear_bit/mount_root） |
| 子进程行为错乱 | fork 重复 mepc += 4 |
| 浮点结果 NaN | fsw/flw 32 位破坏 64 位槽 |
| 输入一个字符卡死 | tty_read 未轮询等整行 |
| 长时间输出丢字 | cli/sti 嵌套不平衡 |
| 退格不擦字 | 缺 ECHOE / 不认 BS |
